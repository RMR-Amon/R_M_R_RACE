# R_M_R Race — игра по локальной сети в браузере

> Чтобы играть через интернет, LAN-сервер не нужен: см. [ONLINE_MULTIPLAYER.md](ONLINE_MULTIPLAYER.md). Этот режим — для игры в одной Wi-Fi без интернета.

2–8 игроков в одной Wi-Fi сети. Сервер запускает **только организатор**; остальным нужен обычный браузер — без установки, без Node.js, без интернета.

## Быстрый старт

### Организатор

Один раз (нужен интернет): установить [Node.js](https://nodejs.org) 20.6 или новее, скачать проект, в его папке выполнить `npm install`.

Каждый раз:

```bash
npm start
```

Команда проверяет Node.js, зависимости и файлы, собирает игру, запускает сервер и **проверяет его на деле**: HTTP, WebSocket, LAN-адрес и UDP. Пример вывода (адрес определяется автоматически):

```
  R_M_R RACE LAN SERVER  v1.3.0

  Status:     RUNNING

  Local:      http://localhost:47800        (this computer)
  LAN:        http://192.168.1.100:47800   <- players open this   [Wi-Fi]

  Discovery:  ACTIVE (UDP 47801; test broadcast sent and received on this computer)
  WebSocket:  ACTIVE
  Players:    0

  Waiting for players…   (Ctrl+C stops the server)
```

Если Windows спросит про брандмауэр — разрешить **Node.js только для частных сетей**.

Затем: открыть `http://localhost:47800` → **Мультиплеер** → **Создать комнату**. Там же виден адрес для игроков с кнопкой копирования и QR-кодом.

### Игроки

1. Подключиться к **той же Wi-Fi сети**.
2. Открыть в браузере адрес организатора (или отсканировать QR-код): `http://192.168.1.100:47800`.
3. Сразу откроется список комнат → **Войти** → **Я готов**.

С сайта https://r-m-r-race.netlify.app тоже можно: «Мультиплеер» → «Игра по локальной сети» → ввести адрес организатора → откроется его игра.

### Где узнать LAN-адрес

В выводе `npm start`, в меню «Мультиплеер» и в лобби. Реальные адаптеры Wi-Fi/Ethernet показываются раньше виртуальных (VPN, VirtualBox, Hyper-V). `localhost` другим устройствам никогда не предлагается.

## Порты

| Порт | Зачем |
|---|---|
| TCP 47800 | игра и WebSocket. Если занят — 47802…47810; фактический порт виден в терминале, в игре, в адресе и в QR-коде |
| UDP 47801 | поиск комнат между серверами |

`RMR_PORT` и `RMR_UDP` задают порты явно (тогда занятый порт — ошибка, без тихой замены). `npm run server` запускает сервер без пересборки.

## Как работает поиск комнат

Браузер не умеет UDP. Комнаты ищут серверы, браузер получает готовый список по WebSocket:

```
браузер ──/agent──▶ сервер организатора ◀──UDP 47801──▶ другие серверы в этой сети
   └───────/play──▶ сервер, на котором находится выбранная комната
```

- Сервер объявляет свои комнаты раз в секунду; молчащий сервер пропадает из списка через 3,5 с, закрытая комната — сразу.
- Поиск работает всё время, пока запущен сервер, а не только при открытом меню.
- Если серверов в сети несколько, видны комнаты всех; вход идёт на настоящий IP и порт нужного сервера.
- Доступность и пинг каждого хоста проверяются раз в 3 с; недоступный помечается, кнопка «Войти» выключается.
- Другая версия игры видна, но войти нельзя: это проверяет и интерфейс, и сам сервер.

## Почему не прямо с Netlify

Страница по HTTPS не может искать устройства в локальной сети и открывать `ws://192.168.x.x` — это защита браузера. Поэтому сайт ничего не ищет и не изображает поиск, а предлагает открыть адрес организатора: обычный переход на другую страницу разрешён. Прогресс (монеты, машины) на сайте и на локальном адресе хранится отдельно: для браузера это разные сайты.

## Синхронизация гонки

Сервер — единственный авторитет. Клиент считает физику своей машины и 20 раз в секунду шлёт состояние (35 байт); сервер проверяет его по настоящей трассе и пределам машины, отклонённое состояние возвращает машину назад. Круги, чекпоинты, места, финиш, попадания и результаты считает только сервер. Чужие машины рисуются с задержкой 110 мс и интерполируются; отсчёт и таймер идут по часам сервера.

| Событие | Что происходит |
|---|---|
| Обрыв связи | автоматическое переподключение до 15 с, гонка продолжается |
| Перезагрузка страницы | возврат в комнату или в идущую гонку на то же место |
| Не вернулся за 15 с | удаляется из комнаты и гонки |
| Организатор комнаты вышел | роль переходит следующему игроку |
| Сервер остановлен | игрокам сообщается сразу; меню показывает «нет связи» и само восстанавливается после запуска |
| Неверный адрес, закрытый порт, сервер молчит | понятная ошибка не позже чем через ≈10 с |

## Безопасность

Сервер отвечает только частным адресам. Запросы с чужих сайтов отклоняются по `Origin`, подмена DNS — по `Host`; CORS открыт только страницам этой сети. Размер сообщений ≤ 4 КБ, ограничение частоты, проверка версии протокола и игры, защита от повтора команд, проверка каждого состояния машины.

Не пробрасывайте порты в интернет и не отключайте брандмауэр: достаточно разрешения для частной сети. Соединение внутри сети не шифруется (HTTP).

## Если комнаты не видны

1. Все в одной сети? Гостевая Wi-Fi обычно изолирует устройства.
2. В роутере выключена «изоляция клиентов» (AP / client isolation)?
3. Сеть в Windows на компьютере организатора — **Частная**, Node.js разрешён (TCP 47800, UDP 47801)?
4. Не открывается даже страница `http://IP:47800` — блокирует сеть или брандмауэр: игра тут ничего сделать не может.
5. Страница открывается, но нет комнат **другого** сервера — заблокирован UDP: введите адрес в «Подключиться по IP».
6. Включён VPN — выключите на время игры.

## Игра без интернета

Интернет нужен только для `npm install`. Дальше достаточно роутера без интернета или точки доступа с телефона. Шрифты встроены, к внешним сайтам игра не обращается.

## Проверка на реальных устройствах (обязательна, автоматически не выполнялась)

**Компьютер организатора:** подключить к Wi-Fi → `npm start` → найти строку `LAN:` → открыть адрес → создать комнату.
**Компьютер игрока:** та же Wi-Fi → в браузере `http://LAN-IP-ОРГАНИЗАТОРА:47800` → найти комнату → войти → «Я готов».

| # | Проверить | Ожидается |
|---|---|---|
| 1 | Два компьютера | видят друг друга, гонка идёт плавно, результаты одинаковы |
| 2 | Телефон по QR-коду | страница открывается, управление с экрана работает |
| 3 | Телефон: свернуть браузер во время гонки | 📡 у других; вернуться ≤ 15 с — продолжает |
| 4 | Выключить и включить Wi-Fi у игрока | ≤ 15 с — продолжает, дольше — удалён |
| 5 | Ctrl+C у организатора | всем сообщается об остановке |
| 6 | Отключить интернет на роутере | всё работает |
| 7 | Два организатора в одной сети | на обоих видны все комнаты |
| 8 | Устройство в другой сети | страница не открывается |
| 9 | Сеть Windows «Общедоступная» | страница не открывается; после смены на «Частную» — открывается |
| 10 | 5–8 устройств | FPS и пинг приемлемы (графика «Низкая» для слабых) |

## Автоматические тесты

```bash
npm run typecheck
npm run test:lan       # сервер, протокол, лобби, гонка 8 игроков, отказы, безопасность
npm run build
npm run test:browser   # обычный Chrome/Edge: 3 браузера, 2 сервера, гонка, обрывы, HTTPS-экран
npm run desktop:e2e    # необязательная Desktop-сборка
```

Последний прогон, один компьютер с Windows 11: typecheck ✔, test:lan 93/93, build ✔, test:browser 46/46 (Chrome, без доступа к интернету), desktop:e2e 20/20. Тесты на одном компьютере **не доказывают**, что конкретные роутер и брандмауэр пропускают трафик между устройствами.

## Desktop-версия (необязательно)

Electron-сборка сохранена и использует тот же сервер (`server/launch.ts`), но для LAN больше не нужна: `npm run desktop`, `npm run dist:win`. Опубликованного установщика нет, сайт на него не ссылается.

Если Electron не нужен, установка быстрее без его файла: `set ELECTRON_SKIP_BINARY_DOWNLOAD=1` (cmd) или `$env:ELECTRON_SKIP_BINARY_DOWNLOAD=1` (PowerShell) перед `npm install`.

## Публикация

GitHub `master` → Netlify → `npm run build` → `dist/`. LAN-сервер на Netlify не запускается. При выпуске новой версии `version` в `package.json` и `GAME_VERSION` в `src/net/config.ts` должны совпадать.

## Известные ограничения

- Организатору нужен компьютер с Node.js; телефон может быть игроком или создать комнату на сервере организатора, но не быть сервером.
- Если компьютер организатора выключится, его комнаты закрываются.
- Движение своей машины считает клиент, сервер его проверяет: грубые читы отсекаются, мелкие отклонения в пределах физики возможны.
- Попадание предмета сообщает жертва, сервер проверяет выстрел; изредка на двух экранах ракета выглядит по-разному. Лаки-блоки и барьеры у каждого свои.
- Браузер в фоне (свёрнутая вкладка) останавливает машину игрока.
- Исключение игрока действует на IP: вторая вкладка на том же устройстве тоже не войдёт 60 секунд.
- В сетевой гонке нет ботов, вступления и паузы.
