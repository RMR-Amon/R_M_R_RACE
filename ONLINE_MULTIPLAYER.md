# R_M_R Race — онлайн-мультиплеер

Игроки открывают https://r-m-r-race.netlify.app из любого города, нажимают **Мультиплеер → Быстрая игра** и попадают в общую гонку. Ничего устанавливать, запускать и вводить адреса не нужно.

- **Сайт** — Netlify (React + Three.js, как раньше).
- **Сервер** — Cloudflare Workers + Durable Objects, тариф Free.
- Старая игра по локальной сети — отдельно, см. [LAN_MULTIPLAYER.md](LAN_MULTIPLAYER.md).

## Как это устроено

```
браузер (Netlify) ──wss /matchmaking──▶ Worker ──▶ Matchmaker   (один объект: очередь, коды, счётчик онлайн)
        └─────────wss /room/<id>──────▶ Worker ──▶ GameRoom     (свой объект у каждой комнаты: лобби, гонка, итоги)
```

| Часть | Файл |
|---|---|
| Вход: проверка источника, лимиты, маршруты | `cloudflare/src/index.ts` |
| Очередь Quick Play, приватные комнаты, «один игрок — одна комната» | `cloudflare/src/matchmaker.ts` |
| Лобби, старт, гонка, переподключение, хранение в SQLite | `cloudflare/src/gameRoom.ts` |
| Настройки и общие функции | `cloudflare/src/env.ts`, `cloudflare/wrangler.toml` |
| Судья гонки (общий с LAN-сервером) | `server/match.ts` |
| Клиент: адрес сервера, подбор, приглашения | `src/net/online.ts` |
| Клиент: соединение, сессия, интерполяция | `src/net/connection.ts`, `session.ts`, `raceLink.ts`, `sync.ts` |
| Экран | `src/components/multiplayer/OnlineMenu.tsx`, `Lobby.tsx` |

### Quick Play

1. Кнопка ставит игрока в очередь. Повторное нажатие или вторая вкладка не создают вторую заявку.
2. Если есть лобби со свободным местом, игрок попадает туда; иначе комната создаётся, как только в очереди 2 игрока. Ботов нет.
3. В лобби идёт отсчёт (20 с; если все нажали «Я готов» — 3 с). Настройки выбирает сервер: случайная трасса, 2 круга. Хоста с особыми правами в Quick Play нет — гонку запускает сервер.
4. Поиск длится до 120 с, потом честное сообщение. Закрытая вкладка сразу выходит из очереди.
5. После гонки — снова лобби. Кто не вернулся с экрана результатов к следующему старту, удаляется из комнаты.

### Приватные комнаты

Код из 6 символов (≈890 млн вариантов, криптослучайный) или ссылка `…/?room=КОД`. Хост меняет настройки, исключает игроков и запускает гонку, когда все готовы. Комната не видна в Quick Play. Войти, зная только id комнаты, нельзя: нужен одноразовый билет от подбора. Подбор кодов ограничен: 8 неверных в минуту с одного адреса. Если хост вышел, роль переходит другому, гонка продолжается.

### Синхронизация гонки и кто решает

Каждый браузер сам считает физику **своей** машины (мгновенное управление) и отправляет её состояние. Комната проверяет каждое состояние на настоящей трассе: скорость, пройденное расстояние за реальное время, выезд за дорогу, прыжки. Недопустимое отклоняется, машина возвращается. Старт, чекпоинты, круги, места, финиш, попадания и результаты считает **только сервер**; объявить себя победителем или изменить чужой результат клиент не может.

Это **серверная проверка, а не полная серверная физика**: мелкие отклонения в пределах возможностей машины сервер не заметит. Попадание предмета сообщает жертва (сервер проверяет, что выстрел был). Лаки-блоки и барьеры у каждого свои.

- 20 положений в секунду, упакованных в 10 сообщений; неизменившееся состояние не отправляется.
- Передаются только числа машины (32 байта на положение), не сцена.
- Чужие машины интерполируются; задержка показа сама подстраивается под сеть (120–600 мс).
- Отсчёт и таймер — по общим часам сервера.

### Потеря связи

| Событие | Что происходит |
|---|---|
| Обрыв | «Связь потеряна», переподключение до 30 с, та же гонка и то же место |
| Перезагрузка страницы | возврат в комнату или идущую гонку |
| Гонка закончилась без игрока | после возвращения он получает результаты |
| Не вернулся за 30 с | удаляется; сообщение и выход в меню |
| Серверный объект перезапущен | комната и гонка восстанавливаются из SQLite (контрольная точка раз в 3 с), игроки переподключаются |
| Игрок не загрузился за 25 с | остальные стартуют без него |

## Публикация (делает владелец аккаунта)

Нужны Node.js 22.12+ и бесплатный аккаунт Cloudflare. Карта не нужна, тариф менять не надо.

1. Создать аккаунт: https://dash.cloudflare.com/sign-up
2. В папке проекта:
   ```bash
   npm install
   npm run online:install
   ```
3. Войти (откроется браузер; пароли и токены никому не передавать):
   ```bash
   cd cloudflare
   npx wrangler login
   ```
4. Опубликовать. Миграция SQLite (`v1`) применится сама; при первом запуске Wrangler попросит выбрать поддомен `workers.dev`:
   ```bash
   npm run deploy
   ```
5. Скопировать показанный адрес вида `https://rmr-race-online.ИМЯ.workers.dev` и открыть `…/health` — должно быть `"ok":true`.
6. Netlify → Site configuration → Environment variables → добавить `VITE_MULTIPLAYER_URL` = этот адрес.
7. Netlify → Deploys → Trigger deploy → **Clear cache and deploy site**.
8. Проверить: сайт → Мультиплеер → вверху «Онлайн: 1». В DevTools → Network → WS видно соединение `wss://…/matchmaking` со статусом 101.

Если домен сайта другой, добавьте его в `ALLOWED_ORIGINS` в `cloudflare/wrangler.toml` и опубликуйте Worker снова.

**Обновления.** Сайт обновляется сам при пуше в `master`, Worker — командой `npm run online:deploy`. Если изменились сообщения, трассы или машины, увеличьте `ONLINE_PROTOCOL` в `src/net/config.ts` и опубликуйте и Worker, и сайт: старые страницы получат «обнови страницу».

## Локальная разработка

```bash
npm run online:dev   # Worker на http://localhost:8787
npm run dev          # сайт на http://localhost:5173 (адрес Worker — в .env.development)
```

Вторым игроком откройте окно инкогнито или другой браузер: вкладки одного браузера — это один игрок.

## Настройки (`cloudflare/wrangler.toml`)

| Переменная | По умолчанию | Значение |
|---|---|---|
| `ALLOWED_ORIGINS` | сайт на Netlify | точные адреса сайтов, которым разрешено подключаться |
| `MIN_PLAYERS` / `MAX_PLAYERS` | 2 / 8 | 8 — предел движка, больше задать нельзя |
| `MATCHMAKING_TIMEOUT` | 120 с | сколько ждать в очереди |
| `ROOM_TIMEOUT` | 600 с | закрытие заброшенного лобби |
| `COUNTDOWN_DURATION` | 4 с | от «все загрузились» до старта |
| `LOBBY_COUNTDOWN` | 20 с | автостарт Quick Play |
| `SEND_HZ` | 10 | сообщений в секунду от машины — **главный расход** |
| `SAMPLE_HZ` | 20 | положений в секунду внутри сообщений |
| `MAX_OPEN_ROOMS`, `MAX_ROOMS_PER_DAY` | 60, 600 | собственные ограничители (0 в день = без ограничения) |
| `DEBUG` | 0 | только для тестов |

## Бесплатные лимиты

Проверено по документации Cloudflare 25.11.2026 (лимиты могут меняться, сброс в 00:00 UTC):

| Ресурс (Free) | Лимит в день |
|---|---|
| Запросы Workers | 100 000 |
| Запросы Durable Objects (20 входящих WebSocket-сообщений = 1 запрос; исходящие бесплатны) | 100 000 |
| Время работы Durable Objects | 13 000 ГБ·с ≈ 28 часов работы одной комнаты |
| SQLite: записано / прочитано строк | 100 000 / 5 млн |
| Хранилище | 5 ГБ всего |

Измерено в тесте: гонка 4 игроков, 110 с — 4436 входящих сообщений (222 запроса) и 66 записанных строк. Со входом и лобби ≈ 250 запросов и ≈ 100 строк.

| Сценарий | ≈ запросов на гонку | ≈ гонок в день |
|---|---|---|
| 2 игрока, 2 мин | 150 | 650 |
| 4 игрока, 2 мин | 270 | 370 |
| 8 игроков, 2 мин | 520 | 190 |
| 8 игроков, 5 мин | 1 250 | 80 |

Это **оценка, а не гарантия**: она предполагает, что 20:1 действует на Free так же, как описано в тарифах, и ничего другого в аккаунте нет. Первым кончается лимит запросов. `SEND_HZ = "6"` даёт примерно в 1,6 раза больше гонок ценой большей задержки. Для постоянных сотен одновременных игроков Free не хватит.

Пустое лобби засыпает и не тратит время работы: таймеров нет, ping обслуживает платформа. Платных привязок нет, тариф сам не повышается: при исчерпании лимита Cloudflare отвечает ошибкой, а игра показывает «Лимит сервиса исчерпан». Если лимит записи кончился во время гонки, она продолжается, но игроки предупреждаются.

Не проверено в настоящем аккаунте: действует ли на Durable Objects ограничение Free в 10 мс CPU на запрос (документация указывает 30 с для Durable Objects). Самое тяжёлое действие — построение трассы при старте: ≈5 мс, в первый раз после запуска до ≈16 мс.

## Безопасность

Подключаются только сайты из `ALLOWED_ORIGINS`; только `wss://`; сообщения ≤ 4 КБ и проверяются; ограничение частоты (за флуд — отключение и блокировка на минуту); одноразовые билеты; секретный токен для возвращения; один игрок — одна комната. Секретов и токенов в репозитории нет.

## Тесты

```bash
npm run typecheck && npm run online:typecheck
npm run online:build          # проверочная сборка Worker без публикации
npm run test:online           # сервер в настоящем workerd: 11 разделов, ≈10 минут
npm run test:online:browser   # сайт в Chrome/Edge, 3 игрока, имитация интернета
```

`npm run test:online -- queue race` запускает отдельные разделы: entry, queue, race, private, reconnect, late, parallel, abuse, hibernation, guessing, limits.

Это симуляция на одном компьютере. Она проверяет логику, но **не доказывает** качество игры через настоящий интернет и поведение настоящего аккаунта Cloudflare.

## Ручная проверка (два и более устройств)

После публикации, лучше в разных сетях (дом и мобильный интернет):

| # | Действие | Ожидается |
|---|---|---|
| 1 | Оба: Мультиплеер → Быстрая игра | одно лобби, отсчёт, общий старт |
| 2 | Проехать гонку | машины движутся плавно, у обоих одинаковые места и время |
| 3 | Закрытая комната, ссылка другу | друг попадает в то же лобби |
| 4 | Выключить интернет на 10 с во время гонки | «Связь потеряна», затем гонка продолжается |
| 5 | Выключить на 40 с | понятное сообщение и выход в меню |
| 6 | Обновить страницу в гонке | возврат на то же место |
| 7 | Телефон | управление с экрана, вход по ссылке |
| 8 | Хост закрывает вкладку | гонка у остальных продолжается |
| 9 | 4–8 игроков | пинг и FPS приемлемы |
| 10 | Cloudflare → Workers → Metrics | расход близок к таблице выше |

## Ограничения

- Игроку с пингом 300+ мс чужие машины показываются с заметным опозданием; столкновения машин приблизительны.
- Все комнаты находит один объект подбора; сама гонка от него не зависит.
- Durable Object создаётся рядом с тем, чей запрос его создал: далёким игрокам пинг выше.
- Свёрнутая вкладка останавливает машину; не загрузившийся игрок исключается.
- Монеты и машины хранятся в браузере, аккаунтов нет.
